01 / METHOD

ONE IMAGE IN.
STRUCTURED JSON OUT.

The task was to identify every purchasable item in a fashion screenshot, classify its product type, describe 11 attributes, and generate a search query. Each model received one image in a single call.

SCREENSHOT→VISION MODEL→ITEMS + ATTRIBUTES + QUERY
TEST SET100 screenshots

8 categories · 46 celebrity looks · 54 everyday looks

MODELS11 vision LLMs

Google, OpenAI, Anthropic, and Alibaba, accessed through OpenRouter

GROUND TRUTH92% consensus coverage

Gemini 3.1 Pro and Claude Sonnet 5.5 labelled each image independently; only agreed items were scored.

A GPT-5.6 Terra audit of 20 images found 100% of included items valid and 97.8% of their attributes correct. Latency is the median end-to-end time per call across 100 images.

The FNDS framework

Four components combine into a 0–100 score. Near misses receive half credit, such as reading trousers as leggings or navy as black.

FFINDS25% · Item recall against ground truth
NNAMES25% · Correct product type, such as kurta versus kurti
DDESCRIBES30% · Colour, pattern, fabric, fit, and other attributes
SSEARCH20% · Key terms present in the generated query

FNDS = 0.25F + 0.25N + 0.30D + 0.20S

04 / THE DECISION

I’D START WITH
GEMINI 3 FLASH.

For live item extraction at scale, it offers the strongest balance in this test: effectively the top quality score, lower cost than the highest scorer, and a 4.7-second median response. Its 98.8 item recall and 98.4 naming score are especially useful when missing or misnaming a garment breaks the downstream search experience.

If API price is the overriding constraint, GPT-5 nano is cheaper. If images must stay in-house, Qwen3-VL is worth considering despite its lower scores and roughly 20-second API latency here.

Scope matters. This is a 100-screenshot, eight-category benchmark with model access through OpenRouter. Prices, latency, and model behavior can change; small score gaps should not be treated as universal rankings. Validate a production choice on your own image mix.
